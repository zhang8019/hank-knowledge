## 一、P0：MinerU 文档解析集成

### 1.1 目标

- 上传 PDF / Office（docx/pptx/xlsx 等）/ 图片时，**自动调用 MinerU 转换为 Markdown**，再走现有索引链路（切块 → BM25/向量）。
- 转换后产物落盘为 `converted/{itemId}.md`，作为 `indexedRelativePath`，**Agent 可快速阅读**（替换现在的"二进制格式不支持"失败路径）。
- 配置 UI 与 embedding/rerank 一致：宿主按 manifest 渲染设置表单。

### 1.2 MinerU API 双模式

MinerU 提供两种 API（详见 https://mineru.net/apiManage）：

| 对比 | ⚡ Agent 轻量 API | 🎯 精准 API |
|------|------------------|-------------|
| Token | **无需**（IP 限频） | 需要（`Bearer <token>`） |
| 文件大小 | ≤ 10MB | ≤ 200MB |
| 页数 | ≤ 20 页 | ≤ 200 页 |
| 输出 | 仅 Markdown（CDN 链接） | Zip（Markdown + JSON，可 docx/html/latex） |
| 接口 | `/api/v1/agent/parse/url`、`/api/v1/agent/parse/file` | `/api/v4/extract/task`、`/api/v4/file-urls/batch` |

**策略**：
- 未配置 Token → **Agent 轻量 API**（开箱即用，≤10MB/20页）
- 配置 Token → **精准 API**（更大文件、批量、结构化 JSON）
- 前端 `upload` 时按文件大小/是否配置 Token 自动选择

### 1.3 配置项（manifest `contributes.configuration`）

| 配置键 | 类型 | 默认 | 说明 |
|--------|------|------|------|
| `mineruBaseUrl` | string | `https://mineru.net` | MinerU API 地址（默认官方；可留空禁用） |
| `mineruApiKey` | string | `""` | MinerU API Token（精准 API 用）；留空 → Agent 轻量 API |
| `mineruModel` | string | `vlm` | 解析模型：`vlm`（推荐）/ `pipeline` / `MinerU-HTML` |
| `mineruLanguage` | string | `ch` | 文档语言（`ch`/`en`/`japan`/`korean` 等） |
| `mineruEnableTable` | boolean | `true` | 表格识别 |
| `mineruEnableFormula` | boolean | `true` | 公式识别 |
| `mineruOcr` | boolean | `false` | 扫描件 OCR |
| `mineruAutoConvert` | boolean | `true` | 导入二进制文件时自动转换；`false` → 仅标记需要转换 |

> 密钥以 string 形式写入插件配置（与 `embeddingApiKey`/`rerankApiKey` 一致），宿主设置页自动渲染，明文存储在宿主配置体系内。

### 1.4 `lib/mineru.ts` 客户端设计

```ts
export interface MineruConfig {
  baseUrl: string;        // 默认 https://mineru.net
  apiKey: string;         // 空 → Agent 轻量 API
  model: string;          // vlm / pipeline / MinerU-HTML
  language: string;       // ch
  enableTable: boolean;
  enableFormula: boolean;
  ocr: boolean;
}

export class MineruClient {
  static fromConfig(store, network): Promise<MineruClient | null>;
  /** 解析本地文件字节 → Markdown（自动选择 Agent/精准 API）。 */
  async parseFile(
    filename: string,
    buffer: Uint8Array,
    opts?: { pageRanges?: string },
  ): Promise<{ markdown: string; mode: "agent" | "standard"; pageCount?: number }>;
  /** 解析远程 URL → Markdown。 */
  async parseUrl(url: string, opts?): Promise<{ markdown: string }>;
  /** 支持的文件扩展名判定。 */
  static supportedExtensions(): string[];
}
```

**Agent 轻量 API 流程**（`parseFile`）：
1. `POST {base}/api/v1/agent/parse/file`，body `{ file_name, language, enable_table, enable_formula, is_ocr }` → 返回 `task_id` + 签名 `file_url`
2. `PUT file_url`，body 原始字节
3. 轮询 `GET {base}/api/v1/agent/parse/{task_id}`（3s 间隔，超时 180s）→ `state=done` 得 `markdown_url`
4. `GET markdown_url` 取 Markdown 文本

**精准 API 流程**（`parseFile`）：
1. `POST {base}/api/v4/file-urls/batch`，body `{ files: [{ name, is_ocr }], model_version }` → 返回 `batch_id` + `file_urls[]`
2. `PUT file_url` 上传字节
3. 轮询 `GET {base}/api/v4/extract-results/batch/{batch_id}` → 每文件 `state=done` 得 `full_zip_url`
4. `GET full_zip_url` 取 Zip → 解析出 `*.md`（用 `fflate` 或系统 `tar`？见 1.5）

### 1.5 Zip 解析（精准 API 的 full_zip_url）

精准 API 返回的是 Zip 包。插件零 npm 运行时依赖，Zip 解包方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| 内置最小 Zip reader | 零依赖，处理 Store/Deflate | 实现 ~150 行，仅支持无加密普通 zip |
| 优先 `Agent 轻量 API` | 直接返回 Markdown，无需解 Zip | ≤10MB/20页 限制 |
| 提交任务时指定 `extra_formats` 单独 Markdown | — | API 返回仍是 Zip |

**决策**：默认优先 Agent 轻量 API（无需解包）；仅当文件 >10MB 或需批量时才用精准 API，此时内置一个最小 Zip（store-only + Deflate via `zlib.inflateRawSync`）解包提取 `*.md`。Node 内置 `zlib`，`Deflate` 解包无需第三方依赖。

### 1.6 workflow 接入（`lib/workflow.ts` 改动）

`runIndexDocument` 的 `readItemSource` 增加分支：

```
file：
  读取 raw 副本字节
  → extract.isTextLike? → 直接解码
  → 否则（PDF/Office/图片）：
      a) item.indexedRelativePath 已指向 converted/*.md → 直接读
      b) 否则若 mineru 已配置且 autoConvert → MineruClient.parseFile
         → 写 raw/converted/{itemId}.md → 更新 indexedRelativePath
         → 返回 markdown
      c) 否则 → 失败："二进制格式，请配置 MinerU 自动转换"
```

`mineru` 转换结果缓存：`indexedRelativePath = converted/{itemId}.md`，reindex 不再重复调用（快照语义，与 URL 快照一致）。

## 二、P1：知识图谱数据层（概要）

### 2.1 `lib/graph.ts`

统一节点-边模型（神经元 / wiki 页 / entity / concept），`maturity` 字段：
- `fuzzy`（探索/wiki）→ `emerging`（共识）→ `codified`（神经树判定单元）

```ts
interface GraphNode {
  id: string;            // nd_xxx
  type: "neuron" | "wiki-page" | "entity" | "concept";
  maturity: "fuzzy" | "emerging" | "codified";
  title: string;
  elements?: { definition; scenario; keyData; triggers[]; tags[]; decisionTemplate?; misjudgmentDefenses[]; checkList[]; source; validity? };
  sourceRefs: string[];  // 关联材料 itemId
  inbound: string[];
  outbound: string[];
  stats: { hitCount; negativeFeedback; lastHitAt; lastUpdatedAt };
}
interface GraphEdge { id; source; target; kind: "synapse"|"wikilink"|"inferred"|"hierarchy"; relation?; strength; bidirectional?; inferredConfidence?; }
```

持久化：`bases/{baseId}/graph.json`（节点索引 + 边）+ `nodes/{nodeId}.json`（节点正文）。

### 2.2 `lib/naming.ts` 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| 神经树文件 | `神经树_《领域名》_v{major}.{minor}.md` | `神经树_《民法典·合同解除》_v1.0.md` |
| 神经元 | `{主干序号}·{动词短语/名词短语}` ≤15字 | `N1·判定解除类型` |
| 主干 | `主干{序号}：{主题}` | `主干1：解除类型` |
| wiki concept | `TitleCase` | `AttentionMechanism` |
| wiki entity | `TitleCase` | `MetaAI` |
| source 页 | kebab-case | `attention-is-all-you-need.md` |

自动命名两级：确定性（slug/章节标题清洗）+ LLM 辅助（神经元「动词+宾语」模板），冲突 `_N` 后缀。

### 2.3 `lib/maturity.ts` 成熟度状态机

```
fuzzy ──多源引用──▶ emerging ──人审+验证──▶ codified
  ▲                                          │
  └────── supersede / 负面反馈×2 ────────────┘（快照降级）
```

硬规则：`emerging→codified` 永不自动，必须过「审查」；`codified→fuzzy` 自动但保留快照。

## 三、P2：神经树构建（概要）

- `lib/tree-builder.ts`：自动建树。输入材料文本 → 领域识别 → 主干划分 → 神经元生成（定义/场景/要点/触发词）→ 落树文件 + graph 节点 + 树内突触 + 全域索引表。
- `lib/verifier.ts`：移植骨架验证器（V1-V17），JS 实现，检查 10 元素完整 / 触发词≥5 / 判定模板≥5步 / 误判防御≥3 / 突触双向 / 出处精确 / 健康度。
- "一本书→一棵树"：自动命名 + 大纲预览 + 确认落树。

## 六、风险与边界

1. **MinerU 依赖外网**：未配置/服务失败时，二进制文件保持原「需要转换」失败态，不阻塞文本类材料。
2. **Token 时效**：MinerU Token 有效期三个月，过期后精准 API 401 → 自动提示；Agent 轻量 API 不受影响。
3. **文件大小**：>200MB 无法解析 → 明确报错提示拆分为多文件。
4. **隐私**：文件字节上传至 MinerU 服务器（第三方），文档中明示；可选仅使用本地文本解析。
5. **零依赖**：Zip 解包仅支持标准 Deflate/Store，不处理加密 zip。
